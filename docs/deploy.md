# Deploying SpendSense

Result: a public frontend URL (Vercel) talking to a public API URL (Render) backed by a managed PostgreSQL database. Total time: about 30 minutes. All accounts have free tiers (check each provider's current limits; free services can sleep when idle, so the first request after a pause may take up to a minute).

```
Browser --> Vercel (Next.js frontend) --HTTPS/WSS--> Render (FastAPI in Docker) --> Render PostgreSQL
```

## 0. Before you start
- The code is on GitHub and CI is green (the **Actions** tab shows a green check).
- You have free accounts on **Render** (render.com) and **Vercel** (vercel.com), both sign-in-with-GitHub.

## 1. Deploy the backend and database on Render
1. Render dashboard -> **New -> Blueprint** -> connect your `spendsense` repository. Render reads `render.yaml` and proposes a web service (`spendsense-api`) and a database (`spendsense-db`).
2. It asks for the values marked `sync: false`:
   - `CORS_ORIGINS`: leave empty for now (set it in step 3).
   - `RAZORPAY_*`: leave empty to disable payments, or paste your **test-mode** keys.
3. Click **Apply**. The first build takes several minutes.
4. When the service is **Live**, open `https://<your-api>.onrender.com/health`. You should see `{"status":"ok"}`. Also open `/docs` for the API explorer.

On every start the container runs `alembic upgrade head` first, so the database tables and views are created automatically.

## 2. Load the demo data into the cloud database
The free tier has no shell, so seed from your own computer:
1. In Render, open the database -> **Connections** -> copy the **External Database URL**.
2. In a terminal in `backend/` (Python environment with `requirements.txt` installed):
   ```bash
   # PowerShell
   $env:DATABASE_URL = "<paste the External Database URL>"
   $env:SECRET_KEY = "unused-for-seeding"
   python -m scripts.seed
   ```
   (If the connection is refused, add `?sslmode=require` to the end of the URL.)
3. This creates `demo@spendsense.com` / `demo12345` with ~5,000 transactions and the synthetic business data.

> Do not seed a database that holds real users: the seed script resets the demo user's transactions.

## 3. Deploy the frontend on Vercel
1. Vercel -> **Add New -> Project** -> import the `spendsense` repository.
2. **Root Directory:** `frontend`. Framework preset: Next.js (auto-detected).
3. **Environment Variables:** `NEXT_PUBLIC_API_URL` = your Render API URL, e.g. `https://spendsense-api.onrender.com` (no trailing slash).
4. **Deploy**, then copy the resulting URL, e.g. `https://spendsense.vercel.app`.

## 4. Connect the two
Back in Render -> `spendsense-api` -> **Environment** -> set `CORS_ORIGINS` to your Vercel URL (comma-separate several). Save; the service redeploys. Without this, the browser blocks the frontend's calls to the API.

## 5. Verify the live site
1. Open your Vercel URL and log in with the demo account.
2. The badge should say **Live** (this proves the WebSocket works over `wss://`).
3. Click **Simulate bank feed**: rows should appear and unusual charges should raise toasts.
4. Click **Upgrade to Pro**. With Razorpay test keys set, the checkout opens; without them you see the friendly "payments aren't set up" message.

## 6. Razorpay webhook (only if you enabled payments)
Razorpay dashboard (Test Mode) -> **Settings -> Webhooks -> Add**:
- URL: `https://<your-api>.onrender.com/billing/webhook`
- Events: `payment.captured`, `order.paid`
- Secret: choose one and put the same value in Render as `RAZORPAY_WEBHOOK_SECRET`.

## Troubleshooting
| Symptom | Likely cause |
|---|---|
| Frontend shows "Could not load your data" | `NEXT_PUBLIC_API_URL` wrong, or `CORS_ORIGINS` missing your Vercel URL |
| First request is very slow | The free API instance was asleep; wait about a minute. The Live badge reconnects by itself |
| Badge stuck on "Reconnecting..." | Browser blocked the socket: check the API URL uses `https` and CORS is set |
| `relation "users" does not exist` | The migration did not run: check the Render deploy logs for the `alembic upgrade head` line |
| 503 on Upgrade | Razorpay keys not set (expected until you add them) |

## Security checklist before sharing the link
- `SECRET_KEY` is generated by Render (never reuse your local one).
- Razorpay keys are **test** keys only.
- The demo password is public by design; do not store real financial data in this deployment.
- Rotate any secret you ever pasted into a chat or screenshot.
