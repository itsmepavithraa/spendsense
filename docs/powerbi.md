# Power BI dashboard guide

This builds a 4-page analytics report on top of SpendSense's data. Power BI never touches the raw app tables: it reads five **SQL views** (created by the `add BI views` migration), which are analysis-ready.

| View | One row per | Used for |
|---|---|---|
| `bi_transactions` | transaction | spend, categories, merchants, anomalies, time patterns |
| `bi_monthly_category` | user x month x category | fast monthly trends |
| `bi_subscriptions` | detected subscription | recurring cost |
| `bi_revenue` | payment | the app's own revenue |
| `bi_users` | user | sign-ups and Pro conversion |

> The revenue and user data is **synthetic** (60 fake sign-ups, ~35% Pro), generated by `backend/scripts/seed.py`, so the business page has something to show. Say so in your portfolio.

## 1. Get the data into Power BI

### Option A: CSV files (no driver needed, recommended)
1. Export the views:
   ```bash
   docker compose exec api python -m scripts.export_bi_csv
   ```
   This writes five files to `backend/data/bi/`.
2. In Power BI Desktop: **Home → Get data → Text/CSV**, and load each of the five files.
   (Or **Get data → Folder** to load them all at once.)
3. In **Power Query**, check the types: `date`, `month_start`, `paid_date`, `signup_date` should be **Date**; `occurred_at`, `created_at`, `paid_at`, `last_charge` **Date/Time**; `amount` and totals **Decimal number**; `is_anomaly` and `is_pro` **True/False**.

### Option B: connect straight to PostgreSQL (live data)
**Get data → PostgreSQL database** → Server `localhost:5432`, Database `spendsense`, mode **Import** → sign in with the `spendsense` database user from your `.env` → pick the five `bi_*` views.
If Power BI complains about the **Npgsql** provider, install it or use Option A.
For anything shared, create a read-only database role for Power BI instead of reusing the app user:
```sql
CREATE ROLE powerbi_reader LOGIN PASSWORD '<choose-a-password>';
GRANT SELECT ON bi_transactions, bi_monthly_category, bi_subscriptions, bi_revenue, bi_users TO powerbi_reader;
```

## 2. Build the data model
Open **Model view** and create these relationships (drag column to column):

| From (one) | To (many) |
|---|---|
| `bi_users[user_id]` | `bi_transactions[user_id]` |
| `bi_users[user_id]` | `bi_revenue[user_id]` |
| `bi_users[user_id]` | `bi_subscriptions[user_id]` |
| `Calendar[Date]` | `bi_transactions[date]` |
| `Calendar[Date]` | `bi_revenue[paid_date]` |

Create the calendar table (**Modeling → New table**), then **Mark as date table** on `[Date]`:
```DAX
Calendar =
ADDCOLUMNS (
    CALENDARAUTO (),
    "Year", YEAR ( [Date] ),
    "Month number", MONTH ( [Date] ),
    "Month", FORMAT ( [Date], "MMM" )
)
```
Also set **Sort by column**: `Month` sorted by `Month number`, and `bi_transactions[weekday]` sorted by `weekday_number`.

## 3. DAX measures
Create these in a table called `Measures` (**Modeling → New measure**):

```DAX
Total Spend       = SUM ( bi_transactions[amount] )
Transactions      = COUNTROWS ( bi_transactions )
Avg Transaction   = DIVIDE ( [Total Spend], [Transactions] )

Anomalies         = CALCULATE ( [Transactions], bi_transactions[is_anomaly] = TRUE () )
Anomaly Rate      = DIVIDE ( [Anomalies], [Transactions] )

Spend Last Month  = CALCULATE ( [Total Spend], DATEADD ( 'Calendar'[Date], -1, MONTH ) )
Spend MoM %       = DIVIDE ( [Total Spend] - [Spend Last Month], [Spend Last Month] )
Spend YTD         = TOTALYTD ( [Total Spend], 'Calendar'[Date] )

Subscription Monthly Cost = SUM ( bi_subscriptions[amount] )
Subscription Yearly Cost  = SUM ( bi_subscriptions[yearly_cost] )

Revenue           = CALCULATE ( SUM ( bi_revenue[amount] ), bi_revenue[status] = "paid" )
Paying Users      = CALCULATE ( DISTINCTCOUNT ( bi_revenue[user_id] ), bi_revenue[status] = "paid" )
Total Users       = DISTINCTCOUNT ( bi_users[user_id] )
Conversion Rate   = DIVIDE ( [Paying Users], [Total Users] )
Cumulative Revenue =
CALCULATE ( [Revenue], FILTER ( ALL ( 'Calendar'[Date] ), 'Calendar'[Date] <= MAX ( 'Calendar'[Date] ) ) )
```
Set formats: spend and revenue as **Currency (INR)** with 0 decimals; rates as **Percentage**.

## 4. Report pages

**Page 1: Overview**
- Cards: Total Spend, Spend MoM %, Transactions, Avg Transaction, Anomalies.
- Line chart: `Calendar[Month]` x Total Spend. In the **Analytics pane**, turn on **Forecast** (3 months) for a built-in forecast.
- Donut: Total Spend by `category`.
- Slicers: `Calendar[Year]`, `category`.

**Page 2: Categories and merchants**
- Treemap: `merchant` sized by Total Spend.
- Matrix: `category` (rows) x `Calendar[Month]` (columns), values Total Spend, with a color-scale background.
- Heatmap-style matrix: `weekday` (rows) x `hour` (columns), values Transactions, to show *when* spending happens.

**Page 3: Anomalies**
- Cards: Anomalies, Anomaly Rate.
- Table: `date`, `merchant`, `category`, `amount`, filtered to `is_anomaly = TRUE`, with data bars on `amount`.
- Scatter: x = `hour`, y = `amount`, legend = `is_anomaly`.

**Page 4: Business and subscriptions**
- Cards: Revenue, Paying Users, Conversion Rate, Subscription Yearly Cost.
- Area chart: Cumulative Revenue by `Calendar[Month]`.
- Funnel: Total Users, Users who started checkout, Paying Users.
- Table: detected subscriptions (`merchant`, `amount`, `charges`, `yearly_cost`).

## 5. Showing it off
- Export **File → Export → PDF**, take screenshots of each page, and put them in `docs/screenshots/`.
- Record a 1-2 minute screen capture clicking slicers.
- **Embedding** a Power BI report inside the web app needs a Power BI Pro/Premium license. **Publish to web** makes the report *public*, so only use it with synthetic data like this. For a resume, screenshots and a video are the safest choice.
